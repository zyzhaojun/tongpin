## 端到端结果

`test-results/app-test.json` 记录的本次结果：

- 实际采集并解码独立 Windows 测试窗口：952 × 590。
- 视频帧从 2 增加到 33，说明接收画面持续更新。
- 接收端 `audioTracks = 0`；当前版本没有声音轨道。
- 测试窗口的绿色画面像素校验通过，排除了只显示黑屏或静态占位图。
- 错误连接信息被拒绝；停止画面后媒体轨道释放，但设备仍保持配对且连接信息不变。
- 切换画面使用现有远端轨道，调整到 720p 不会断开配对；停止后再次开始也复用当前配对。
- 只有主动断开才释放会话并生成新的连接信息。
- F11 全屏和 Esc 退出全屏通过。
- 全屏状态来自 Electron 的进入/退出事件，不再通过窗口尺寸猜测；视频舞台从 `(0,0)` 覆盖完整视口，应用顶栏、标题区和页脚均隐藏。
- 发现结果只含设备名、地址、端口和 TLS 指纹标识，不含备用连接密钥；接收端允许后才建立会话。

## 两台物理电脑实测

0.1.1 在 `192.168.1.105 → 192.168.1.128` 的 Wi-Fi 环境完成 20 秒视频实测。首次失败的根因是接收端 Windows 防火墙静默丢弃 TCP 48765；添加 `LocalSubnet` 入站规则后，TLS、WSS 和 WebRTC 均通过。记录见 `test-results/physical-lan-test.json`：932 × 552、12–13 fps、0.1–0.2 Mbps，往返通常 3–10 ms，最高采样 32 ms。

## 范围和限制

0.2.0 的自动发现、接收端确认和画面传输已由用户在上述两台物理电脑确认成功。0.2.1 的全屏修复已完成双进程自动化测试，仍需在目标大屏复验：

- 两台物理 Windows 电脑之间的 Wi-Fi/有线互通。
- 学校网络的终端隔离、访客网络策略和 Windows 防火墙策略。
- 教学一体机或电视连接电脑的具体显示分辨率、缩放比例和长时间稳定性。

首次讲座前应使用目标笔记本和大屏电脑完整走一遍 [使用说明](使用说明.md)，并记录校园网络是否允许 TCP 48765 和 WebRTC 动态端口互访。
